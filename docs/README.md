# Design documentation

Design documents for the pull-printing app. They describe what the screens should be, why, and how fast the main task must be.

| Document | What it covers |
|---|---|
| [01 Product brief](01-product-brief.md) | Who uses it, the one job it must do fast, speed targets, scope |
| [02 User flows](02-user-flows.md) | Step-by-step flows for printing, releasing and administering |
| [03 Screen specs](03-screen-specs.md) | Each mockup with its purpose, contents, states and exact wording |
| [04 Design guidelines](04-design-guidelines.md) | Colours, type, sizes, accessibility, and what we will not use |
| [05 Open decisions](05-open-decisions.md) | Questions that change the design and need an answer |
| [06 Hosting the demo](06-demo-hosting.md) | Putting the demo online for free, settings, what to expect |

## Mockups

- Images used in the documents: [`design/screens/`](design/screens/) (PNG, 2x).
- Editable source for each screen: [`design/source/`](design/source/) (`.dc.html`, one per screen). These come from the Claude Design canvas and open in it. Opened directly in a browser they render as a flat screen.

The screens are mockups, not Flutter code. Sample names and numbers are made up.
